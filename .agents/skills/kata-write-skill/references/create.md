# Create an original skill

Use this route when no source skill exists and a real task or repeated failure
shows a reusable need.

1. Name the concrete request, failure, or repeated decision that created the
   need. Do not start from an abstract topic alone.
2. Check the current library for the same outcome or a conflicting trigger.
   Revise the canonical skill when it already owns the job.
3. Define the observable output, acceptance evidence, selection boundary,
   discretion, authority limits, escalation conditions, required capability,
   recovery after failure, and stop conditions.
4. Write the faceted metadata from the library contract. Select the subject by
   the knowledge needed to judge the result. Keep practice, object, profile,
   authority, inputs, and outputs separate.
5. Build the smallest package that can improve the real task. Add support files
   only when they have a clear consumer.
6. Test the package against the task that caused the need. Add at least one
   non-trigger or failure case when it protects an important boundary.

An original skill has no external attribution. Record external ideas only when
they materially shaped the text or behavior and their rights permit reuse.
